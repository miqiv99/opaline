存储模型和架构

工作区模型

MyNotes/
  notes/
    index.html
    projects/
      opaline.html
  assets/
    images/
    files/
  .opaline/
    index.sqlite
    settings.json
    cache/
  • notes/ 保存用户创作的持久 HTML 笔记。
  • assets/ 保存图片和附件。
  • .opaline/ 保存可重建的应用元数据和缓存。
  • 删除 .opaline/index.sqlite 不应导致用户内容丢失。
  • 工作区应该在普通文件浏览器中保持可查看。

存储原则

HTML 文件是规范数据源。SQLite 是有用的、快速的、可重建的。

文件系统保存持久内容

  • HTML 笔记
  • 图片
  • 附件
  • 导出的资源

SQLite 保存派生数据

  • 搜索索引
  • 反链
  • 出链
  • 标签
  • 标题和别名
  • 最近笔记
  • 收藏
  • 工作区设置
  • AI 嵌入向量（如果启用）
  • 缓存元数据

身份模型

Opaline 应该区分身份和位置。

  • 笔记 ID 应该是稳定的 UUID 风格标识符。
  • 路径是面向用户的位置，可能会改变。
  • 链接应同时保存 href 和稳定的 Opaline 目标 ID。
  • SQLite 可以解析 ID、路径、标题、别名、反链和断链。

架构分层

React UI
  -> 编辑器层
  -> 领域层
  -> 存储适配器
      -> Tauri 桌面文件系统
      -> Tauri 移动文件系统
      -> Web IndexedDB 或 OPFS

各层职责

笔记格式层

  • 解析 HTML
  • 序列化 HTML
  • 规范化保存的文档
  • 验证 Opaline HTML Profile
  • 迁移旧版本笔记

领域层

  • 笔记身份
  • 笔记元数据
  • 链接和反链
  • 标签
  • 资源管理
  • 搜索索引
  • 发布元数据

编辑器层

  • Tiptap 扩展
  • 编辑命令
  • 粘贴净化
  • 选区行为
  • 富块编辑
  • 撤销和重做行为

这套设计的核心是信任：用户内容属于文件系统，数据库只是让体验更快、更聪明。
