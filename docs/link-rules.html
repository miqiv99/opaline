Link Rules

[[note]] Links

When saving, Opaline compiles [[Title]] into ordinary browser-readable HTML links. If the target note can be resolved by title, it is saved as:

<a href="target.html" data-opaline-link="note-id" data-opaline-link-kind="note">Title</a>

If the target note cannot be found, Opaline saves an unresolved span and marks it as a broken link in the index:

<span data-opaline-unresolved="Title">[[Title]]</span>

Four Relationship Types

The data model and graph view now distinguish four relationship types. The ordinary-user context-menu flow for creating concept-level links from selected text is still not implemented.

  • File-level: links to a note.
  • Heading-level: links to a heading inside a note.
  • Block-level: links to a stable paragraph, card, table, quote block, or other block.
  • Concept-level: links to a concept node. Tags are currently used as concept nodes in the graph.
<a href="target.html" data-opaline-link="note-id" data-opaline-link-kind="note">Target note</a>
<a href="target.html#Research-Question" data-opaline-link="note-id" data-opaline-link-kind="heading">Research Question</a>
<a href="target.html#b-intro" data-opaline-link="note-id" data-opaline-link-kind="block" data-opaline-block-id="b-intro">intro block</a>
<a href="opaline://concept/RAG" data-opaline-link-kind="concept" data-opaline-concept="RAG">RAG</a>

The graph renders these as different edge types: file, heading, block, and concept. This allows filtering by relationship type instead of treating every link as the same kind of edge.

Ordinary <a> Links

  • http:, https:, mailto:, and tel: are external links and are not broken links.
  • #block-id is treated as an internal anchor in the current note.
  • Relative paths that resolve to HTML notes inside the workspace notes/ directory record the target note id.
  • Relative paths that cannot be resolved are marked as broken links.
  • If link text equals a note title, Opaline may use that title as a fallback target.

Block References

Block references are represented with URL hashes and Opaline metadata:

<a href="target.html#b-intro" data-opaline-link="note-id" data-opaline-link-kind="block" data-opaline-block-ref="b-intro" data-opaline-block-id="b-intro">target#b-intro</a>

The current version resolves whether the target note exists. Verifying whether the exact block id exists can be added at the index layer later.

Broken Links

The following cases are marked as broken links:

  • [[Title]] cannot be resolved to a note.
  • A relative HTML link cannot find its target note.
  • data-opaline-link points to a missing note id.
