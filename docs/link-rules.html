Link Rules

Title Shortcut Links

When saving, Opaline compiles a title shortcut such as [[Title]] into an ordinary browser-readable HTML link. If the target note can be resolved by title, it is saved as:

<a href="target.html" data-opaline-link="note-id" data-opaline-link-kind="note">Title</a>

If the target note cannot be found, Opaline saves an unresolved span and marks it as a broken link in the index:

<span data-opaline-unresolved="Title">[[Title]]</span>

Four Relationship Types

The data model and relationship-map view now distinguish four relationship types. The editor now exposes ordinary-user flows for copying the current block link and inserting links to headings or blocks in the current note. Concept-link creation from selected text is still a later step.

  • File-level: links to a note.
  • Heading-level: links to a heading inside a note.
  • Block-level: links to a stable paragraph, card, table, quote block, or other block.
  • Concept-level: links to a concept node. Tags are currently used as concept nodes in the relationship map.
<a href="target.html" data-opaline-link="note-id" data-opaline-link-kind="note">Target note</a>
<a href="target.html#Research-Question" data-opaline-link="note-id" data-opaline-link-kind="heading">Research Question</a>
<a href="target.html#b-intro" data-opaline-link="note-id" data-opaline-link-kind="block" data-opaline-block-id="b-intro">intro block</a>
<a href="opaline://concept/RAG" data-opaline-link-kind="concept" data-opaline-concept="RAG">RAG</a>

The relationship map renders these as different edge types: file, heading, block, and concept. This allows filtering by relationship type instead of treating every link as the same kind of edge.

The full relationship-map view can focus on the active note's context and lets users click an edge to inspect its relationship type, source, target, and any heading, block, or concept metadata.

Ordinary <a> Links

  • http:, https:, mailto:, and tel: are external links and are not broken links.
  • #block-id is treated as an internal anchor in the current note.
  • Relative paths that resolve to HTML notes inside the workspace notes/ directory record the target note id.
  • Relative paths that cannot be resolved are marked as broken links.
  • If link text equals a note title, Opaline may use that title as a fallback target.

Block References

Block references are represented with URL hashes and Opaline metadata:

<a href="target.html#b-intro" data-opaline-link="note-id" data-opaline-link-kind="block" data-opaline-block-ref="b-intro" data-opaline-block-id="b-intro">target#b-intro</a>

The editor preserves data-opaline-block-id in Tiptap state and can generate missing IDs before creating a block link. The current index resolves whether the target note exists; exact cross-note block-id verification remains an index-layer follow-up.

Live Components and Extensions

Live components are represented as controlled, readable HTML. Settings separate built-in widgets, installed extension widgets, and experimental script notes.

<opaline-widget type="local-graph" title="Current note context">Opaline widget: Current note context</opaline-widget>
<opaline-widget type="network-status" target="192.168.1.1" endpoint="/status" profile="onu-readonly">Opaline widget: Network status</opaline-widget>
<opaline-script title="Experimental script" language="javascript">const status = await opaline.net.fetch("http://192.168.1.1/status");</opaline-script>

Opaline may render built-in widget types such as query, chart, and local-graph. Extension widgets are handled by scripts installed under .opaline/plugins, with manifest.json mapping widget types to script files while notes store only parameters. <opaline-script> remains the per-note experimental script escape hatch.

Broken Links

The following cases are marked as broken links:

  • A title shortcut cannot be resolved to a note.
  • A relative HTML link cannot find its target note.
  • data-opaline-link points to a missing note id.
