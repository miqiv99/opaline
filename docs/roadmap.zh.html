路线图和暂不做的事

阶段 0：地基

  • 初始化 Tauri 和 React。
  • 选定包管理器和代码格式化工具。
  • 接入 Tiptap 编辑器基线。
  • 接入 SQLite。
  • 定义第一版 Opaline HTML Profile。
  • 确定默认工作区目录约定，并记住用户手动选择的位置。
  • 添加基础测试和构建命令。

阶段 1：可信的本地笔记

  • 启动时自动初始化默认本地工作区。
  • 设置页支持更改工作区位置。
  • 创建笔记。
  • 用 Tiptap 编辑。
  • 保存为干净 HTML。
  • 加载已有 HTML 笔记。
  • 自动保存更改。
  • 从文件重建 SQLite 元数据。
  • 显示文件树和最近笔记。

阶段 2：搜索和导航

  • 标题搜索。
  • 正文搜索。
  • 标题提取。
  • 标签提取。
  • 最近笔记。
  • 收藏。
  • 基础命令面板。
  • 断链检测。

阶段 3：知识链接

  • [[笔记链接]]。
  • 将链接解析到稳定 ID。
  • 在图谱数据模型里区分文件级、标题级、块级、概念级关系。
  • 完整图谱支持当前笔记邻域和边详情查看。
  • 笔记移动时更新链接。
  • 反链。
  • 出链。
  • 断链检测。
  • 日记。
  • “今天”对话入口，并把用户和 AI 回合追加到当天 HTML 日记。
  • 带关系类型过滤的完整图谱视图。

阶段 4：富 HTML 块

  • 表格。
  • 任务列表。
  • 标注块。
  • 代码块。
  • 图片和附件。
  • 嵌入。
  • 数学公式。
  • 图表。
  • 块 ID。
  • 块引用。
  • 普通用户可以在编辑器里复制当前块链接，并插入标题或块链接。
  • 受控内置活组件占位，例如 <opaline-widget type="local-graph">，不开放笔记任意脚本。
  • 概念标记，以及普通用户能从右键菜单创建概念关系的交互。

阶段 5：AI 辅助知识工作

  • 设置页配置 AI provider、自定义 API 地址、模型、API Key、模型测试和模型抓取。
  • 用户在“今天”里随手说的话先本地记录，再由 AI 接着回应。
  • 总结笔记。
  • 生成标题。
  • 提取标签。
  • 推荐相关笔记。
  • 检测重复或重叠笔记。
  • 将草稿转为大纲。
  • 将长笔记重构为更小的链接笔记。
  • 带引用向工作区提问。
  • 将导入的 Markdown 或网页转换为干净的 Opaline HTML。

阶段 6：发布

  • 选择要发布的笔记。
  • 生成静态 HTML 站点。
  • 包含资源文件。
  • 包含搜索索引。
  • 包含反链和目录。
  • 支持基础自定义主题。
  • 保留公开和私密的边界。

阶段 7：读者搜索和公开知识

  • 发布页面的选中即搜。
  • 在当前作者范围内搜索。
  • 展示相关公开笔记。
  • 带引用的 AI 解释。
  • 公开词汇表或概念页面。
  • 可选的 Diandanr 集成。

阶段 8：同步、移动端、插件

  • 云文件夹兼容。
  • Git 友好的工作流。
  • 可选的托管同步。
  • 移动端探索。
  • Web 存储适配器。
  • 主题 API。
  • 插件 API。
  • 工作区自动化钩子。
  • 更改工作区位置时迁移旧工作区文件。

已知残留问题

  • 块链接能打开目标笔记并滚动到目标块，但目标块的可视高亮在桌面编辑器里仍不稳定，当前可能看不到。后续需要单独修复跳转后的高亮定位和渲染。

暂时不做

  • 实时多人协作
  • 完整的公开论坛
  • 社交推荐信息流
  • 插件市场
  • Notion 风格数据库
  • 复杂项目管理
  • 移动端优先编辑
  • 托管同步
  • 一体化网站生成
  • 跨用户 AI 搜索

这个路线的目的，是避免一开始就被平台、社区、同步、插件市场和网站生成器这些复杂任务拖住。先让个人工具成立，再谈公开网络。
