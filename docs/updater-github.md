# Opaline GitHub Release Updater

Opaline uses the Tauri 2 updater plugin for the public alpha update flow. The app only checks when the user clicks the update button in Settings, and installation requires a second explicit button press.

The active `src-tauri/tauri.conf.json` is configured for GitHub Releases at `miqiv99/opaline`. The private signing key stays outside the repository.

Keep the updater entry as an object even before GitHub is configured:

```json
"plugins": {
  "updater": {
    "pubkey": "",
    "endpoints": []
  }
}
```

Do not set `plugins.updater` to `null`. The updater plugin is registered in Rust, and Tauri expects `plugins.updater` to deserialize as a config object. A `null` value can make `npm run tauri:dev` start Vite successfully and then panic when the desktop app initializes.

## One-time setup

1. Generate a Tauri updater signing key and store the private key somewhere outside the repo.

```powershell
npm run tauri signer generate -- -w "$env:USERPROFILE\.tauri\opaline-updater.key"
```

2. Copy the generated public key into `src-tauri/tauri.conf.json`, replacing the empty `pubkey`, and add the real endpoint under `endpoints`.

The endpoint below follows GitHub's "latest release" redirect, so it is best for regular published releases. If you mark Opaline alpha builds as GitHub pre-releases, use a stable channel JSON URL that you control instead, because GitHub's latest release endpoint excludes pre-releases.

```json
{
  "bundle": {
    "active": true,
    "targets": "all",
    "icon": [],
    "createUpdaterArtifacts": true
  },
  "plugins": {
    "updater": {
      "pubkey": "PASTE_GENERATED_PUBLIC_KEY_HERE",
      "endpoints": [
        "https://github.com/miqiv99/opaline/releases/latest/download/latest.json"
      ],
      "windows": {
        "installMode": "basicUi"
      }
    }
  }
}
```

3. Keep the private key out of git. For local release builds, set it in the PowerShell session before building.

```powershell
$env:TAURI_SIGNING_PRIVATE_KEY="$env:USERPROFILE\.tauri\opaline-updater.key"
npm run tauri:build
```

If the key has a password, also set `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`.

## GitHub release assets

For each release, upload:

- the Windows installer generated by Tauri, such as the `.msi` or `setup.exe`
- the matching `.sig` file generated next to that installer
- a `latest.json` file that points at the installer URL and embeds the text content of the `.sig` file

Example `latest.json`:

```json
{
  "version": "0.1.2",
  "notes": "Short release notes for Opaline 0.1.2.",
  "pub_date": "2026-05-19T00:00:00Z",
  "platforms": {
    "windows-x86_64": {
      "signature": "PASTE_CONTENTS_OF_INSTALLER_SIG_HERE",
      "url": "https://github.com/miqiv99/opaline/releases/download/v0.1.2/Opaline_0.1.2_x64-setup.exe"
    }
  }
}
```

The `version` should be higher than the version in `src-tauri/tauri.conf.json` and `package.json`. The `signature` value is the contents of the `.sig` file, not a URL to that file.

## Safety notes

- Do not upload the private signing key.
- Do not enable automatic background installation during the public alpha.
- Test with a non-essential workspace before announcing an update.
- If the signing key is lost, already installed copies cannot trust future update packages signed by a new key.
