愿景和定位

产品定位

Opaline 是一个以干净 HTML 为原生笔记格式的本地优先知识工作台。

它从一个个人桌面笔记应用起步，但更大的愿景是：笔记应该是持久的本地文档，可以被舒适地编辑、深度搜索、相互链接、发布为网页，并最终由 AI 带引用地查询。

核心理念

Obsidian 证明了本地 Markdown 文件可以成为严肃的个人知识库。Opaline 探索的是一个相关但不同的赌注：

富知识笔记应该以干净的本地 HTML 保存，因此每篇笔记从一开始就是可阅读的文档、可发布的网页、也是 AI 辅助整理的结构化知识源。

为什么不是 Markdown

如果 Markdown 已经能做好个人知识管理——Obsidian 证明了这一点——那为什么要用 HTML？

简短的答案是：Markdown 是一种书写速记法，HTML 是一种文档格式。当笔记量小、语言单一时，这个差别不重要。当笔记变得复杂时，差距会越来越大。

以下是 HTML 原生能表达、而 Markdown 做不到（或只能靠互不兼容的扩展来做）的事情：

语言边界

在 HTML 中，段落知道自己的语言：<p lang="zh">中文</p><p lang="en">English</p>。在 Markdown 中，两个相邻段落只是纯文本，没有解析器能区分语言。这对双语搜索（"只搜我的英文笔记"）、拼写检查、屏幕阅读器、以及需要知道段落语言再去做嵌入的 AI 检索来说，是质的区别。

稳定的块标识

HTML 允许每个章节带持久 ID：<section id="b-db-choice" data-opaline-block>。你可以链接到它，调整顺序和编辑后链接仍然有效，反链解析正确。Markdown 没有块标识的概念——块引用依赖脆弱的文本匹配或标题自动生成的 slug，标题一改链接就断。

富文档原生元素

定义列表、图表说明、旁注、折叠部件——<dl>、<figure>、<aside>、<details> 都是标准 HTML。在 Markdown 中，每一样都需要不同的插件或直接写 raw HTML 来绕过。

无损往返

Markdown → HTML → Markdown 是有损的。哪个 flavor？哪些扩展？你写的 --- 是水平线还是 YAML frontmatter？HTML → 编辑 → HTML 没有转换步骤，因此不会有任何丢失。

这些不是在说 Markdown 不好。而是说 Markdown 为书写优化，HTML 为成为文档本身优化。Opaline 的赌注是：对于长期知识来说，文档格式比打字速记法更重要。

与 Obsidian 的关系

Obsidian 证明了市场：本地文件、wiki 链接和插件生态可以成为严肃的知识工具。Opaline 不是在 Obsidian 擅长的领域和它竞争。

区别是结构性的：

  • Obsidian 建立在 Markdown 上，靠插件扩展（Dataview 做查询、Callouts 做标注、Canvas 做可视化布局）。这些都是执行得很好的变通方案——但它们是变通方案，因为底层格式本就不是为富结构设计的。
  • Opaline 的赌注是：从更丰富的格式出发，让核心不做插件就能做更多事：结构化元数据是原生 HTML 时不需要 Dataview，<aside> 存在时不需要 Callout 语法，块自带 ID 时不需要 Canvas JSON。

Obsidian 用户真正要问的不是"应不应该换"，而是"我的知识工作有没有复杂到 Markdown 的天花板已经开始限制我了"。Opaline 是为感觉到那个天花板的人准备的。

第一用户

第一用户是作者，而不是公开读者。Opaline 应该服务于随着时间积累知识的人：研究者、写作者、开发者、学生、产品思考者和技术创作者。

第一产品闭环

写下来 -> 存得住 -> 找得到 -> 连得上 -> 以后能发布

长期方向可以向公开知识网站和面向读者的 AI 搜索发展，但前提是本地知识系统足够可靠。

产品原则

  • 默认本地优先。
  • HTML 文件是真实数据源。
  • SQLite 索引可重建。
  • 笔记应该在没有安装 Opaline 的情况下仍然可用。
  • 编辑器应该感觉快速、安静、严肃。
  • 搜索应该帮助用户找回旧上下文，而不仅仅是匹配关键词。
  • AI 应该提议、解释和引用。它不应该悄悄地重写知识。
  • 发布应该是文件格式的自然结果，而不是第一个产品。
  • 公开和社区功能应该在个人工具稳定之后再考虑。
  • 当服务端功能（发布、同步、公开搜索）引入后，本地核心必须在不依赖它们的情况下完全可用。本地是地基，服务端是叠加层。

与 Diandanr 的关系

Opaline 和 Diandanr 最终可以互补，但暂时应该保持独立。

Opaline  = 本地知识创建和管理
Diandanr = 发布、网站生成、分发和平台功能

阶段性目标

  • 短期：让个人能放心把真实笔记交给 Opaline。
  • 中期：让笔记能被搜索、链接、整理和 AI 检索。
  • 长期：让公开笔记成为可阅读、可引用、可追问的知识网络。

Opaline 的第一性问题不是"能做多少功能"，而是"能不能长期保存和理解用户自己的知识"。
