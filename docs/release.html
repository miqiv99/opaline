Build and Release Notes

Opaline is in public alpha. Release builds are currently intended for testing and early feedback.

Commands

npm install
npm run tauri:dev
npm run tauri:build

Tauri bundle outputs are written under the target-specific release bundle directory, such as src-tauri/target/release/bundle/ or src-tauri/target/aarch64-apple-darwin/release/bundle/.

Manual Updates

The Settings page now includes a manual check-for-updates flow built on the Tauri updater plugin.

  • Opaline checks only when the user clicks the update button.
  • Installing an available update requires a second explicit confirmation.
  • The active updater configuration points at GitHub Releases and is used by the manual update check.
  • Do not set plugins.updater to null; Tauri expects an updater config object and the app can panic during startup if the plugin config is null.
  • Current signed update metadata for v0.1.2 is tracked at release-assets/v0.1.2/latest.json.

GitHub updater setup: updater-github.md

Alpha Workspace Safety

Before testing alpha builds with important notes, use Settings → Workspace backup to create a timestamped backup folder. The backup includes notes/, assets/, .opaline/settings.json, and .opaline/history/ when present. It skips .opaline/cache/ and the derived SQLite index by default.

  • Migration previews source and target paths, file count, byte size, unreadable files, recursive path risks, and overwrite conflicts.
  • Targets with existing content are rejected rather than merged.
  • Migration copies into a temporary target, verifies the copy, updates the active workspace path, and leaves the old workspace untouched.
  • Failed backup or migration attempts should leave the source workspace unchanged and remove temporary output.

SQLite index drift after migration is recoverable with the explicit rebuild command because HTML notes remain the durable source of truth.

Platform Notes

  • Windows packages should be built on Windows. Unsigned builds may trigger SmartScreen warnings.
  • macOS Apple Silicon packages are built and tested on macOS. Public distribution usually needs signing and notarization.
  • Linux support is future-facing until packages are explicitly tested and documented.
