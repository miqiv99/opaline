Build and Release Notes

Opaline is in public alpha. Release builds are currently intended for testing and early feedback.

Commands

npm install
npm run tauri:dev
npm run tauri:build

Tauri bundle outputs are written under src-tauri/target/release/bundle/.

Manual Updates

The Settings page now includes a manual check-for-updates flow built on the Tauri updater plugin.

  • Opaline checks only when the user clicks the update button.
  • Installing an available update requires a second explicit confirmation.
  • The active updater configuration is intentionally inert until a real release channel exists.
  • Do not set plugins.updater to null; Tauri expects an updater config object and the app can panic during startup if the plugin config is null.
  • Until GitHub release assets, latest.json, and the updater signing key are configured, update checks may report that the update source is not configured.

GitHub updater setup: updater-github.md

Platform Notes

  • Windows packages should be built on Windows. Unsigned builds may trigger SmartScreen warnings.
  • macOS packages should be built and tested on macOS. Public distribution usually needs signing and notarization.
  • Linux support is future-facing until packages are explicitly tested and documented.

Release Configuration Gaps

  • Review the Tauri app identifier.
  • Configure bundle icons.
  • Document whether each release is signed or unsigned.
  • Configure the Tauri updater signing key and endpoint.
  • Upload GitHub Release assets and latest.json.
  • Add release notes, checksums, and migration notes.
