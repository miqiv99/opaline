Data and Privacy

Opaline is designed as a local-first desktop knowledge workspace.

Workspace Data

Documents/
  Opaline/
    notes/
    assets/
    .opaline/
  • notes/ stores durable HTML notes.
  • assets/ stores images and attached files.
  • .opaline/ stores app metadata, indexes, settings, cache, and history snapshots.

Network and AI

Local note editing does not require a cloud account. Network access can happen when users configure AI providers, fetch model lists, run extensions or scripts, or open external links.

AI keys are user-provided secrets. Public alpha builds should not be used with sensitive production credentials unless the user has reviewed the code and understands the risk.

Backups

Before testing alpha builds with important notes, use the built-in workspace backup flow or make a manual copy of the workspace folder.

The built-in backup creates a timestamped folder such as opaline-backup-YYYYMMDD-HHMMSS/. It includes notes/, assets/, .opaline/settings.json, and .opaline/history/ when present. It skips .opaline/cache/ and the derived SQLite index by default.

Backup and migration both preflight readable files and target writability, write to temporary folders first, and remove temporary output on failure. Migration is copy-first: after verification Opaline points at the new workspace, while the old workspace remains at its original path.
