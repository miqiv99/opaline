Opaline

A local-first knowledge workspace built around clean HTML as the native note format.

Public alpha: Opaline is suitable for testing and early feedback, but it is not yet a stable daily-driver release. Windows is the primary active development target; macOS builds should be produced and tested on macOS.

Release and community documents: release notes, data and privacy, changelog, contributing, and security.

Rich knowledge notes should be stored as clean local HTML, so every note is already a readable document, a publishable webpage, and a structured source for AI-assisted organization.

Core Thesis

Opaline should not begin as a social platform, forum, website builder, or clone of an existing notes app. The first product should be a reliable local tool for one person.

speak -> auto-record -> save -> search -> link -> publish later

The long-term direction can grow toward public knowledge sites and reader-facing AI search, but only after the local knowledge system is trustworthy.

Current Product Loop

The current prototype starts with 认真记记, a focused knowledge workspace for deliberate note work. The earlier casual Today entry is currently hidden while the serious workspace is polished for the public alpha.

  • Opaline auto-initializes a default workspace in the user's documents folder under Opaline.
  • Users create and edit clean local HTML notes in the focused workspace.
  • The serious workspace has a left ribbon, collapsible file pane, main HTML editor, and collapsible right inspector.
  • The right inspector contains note operations, outline, outgoing links, mentions, and a compact relationship-map preview.
  • Settings owns workspace location, AI provider, custom API base URL, model, API key, model testing, model fetching, and the live-component/plugin policy.
  • Changing the workspace location is remembered; file migration from the previous workspace is the next needed step.

Current Implementation Status

The app is no longer only a scaffold. It already has the first usable desktop loop.

  • Tauri + React + Tiptap app shell.
  • Automatic default workspace under the user's documents folder.
  • Local HTML note creation, loading, editing, saving, and auto-saving.
  • Daily journal creation remains available from the app, while the old casual Today entry is hidden for the public alpha.
  • AI settings with provider selection, custom API base URL, model, API key, explicit save, model testing, and model fetching.
  • Clean Opaline HTML Profile helpers and tests.
  • SQLite-backed metadata and search direction, with FTS participation already introduced for search.
  • Link scanning for normal links, wiki-style note links, block references, mentions, outgoing links, and broken links.
  • Relationship data now distinguishes file-level, heading-level, block-level, and concept-level links for relationship-map modeling.
  • The editor can copy the current block link and insert links to headings or blocks in the current note using stable block IDs.
  • Settings now include an extension panel with plugin protection, install status, refresh, and an action to open .opaline/plugins.
  • <opaline-widget> can store built-in widgets and installed plugin widgets such as network-status. Notes store parameters such as type, target, endpoint, and refresh; scripts live in the workspace plugin folder.
  • <opaline-script> exists as an experimental script note. When enabled in Settings, it runs JavaScript inside Opaline and can update the card with opaline.render() or call HTTP/HTTPS APIs through opaline.net.fetch().
  • Rich editor blocks for callouts, two-column layouts, comparison layouts, sidenotes, disclosure blocks, tables, task lists, images, embeds, math, and Mermaid diagrams.
  • Editor right-click menus for common formatting, paragraph styles, H1-H6 headings, insert actions, and clipboard actions.
  • File-pane right-click menu for opening, duplicating, favoriting, copying note paths, and opening local history.
  • Built-in local note history stores HTML snapshots in workspace metadata. It is not Git, does not require Git to be installed, keeps the last 30 days by default, and restores only after preview and confirmation.
  • Focused knowledge workspace with a left ribbon, file explorer, collapsible left/right panels, relationship-map preview, and a full relationship view with relation-type filters, current-note context mode, and edge details.

Still rough: workspace migration is not implemented yet, ordinary-user UI for creating concept-level links from selected text is not implemented yet, file operations need more polish, and the HTML-native editor interactions need more polish.

Known residual issue: block links can open the target note and scroll to the target block, but the visible target highlight is still unreliable in the desktop editor and may not appear. This should be fixed in a focused follow-up.

HTML-Native Differentiators

  • Live components / Web Components: Settings keep built-in widgets and experimental script notes separate, while third-party widgets are loaded from .opaline/plugins/<plugin-id>/. A plugin manifest.json maps component types such as network-status to script files; notes store parameter declarations such as <opaline-widget type="network-status" target="192.168.1.1" endpoint="/status">.
  • DOM-level atomic links: blocks keep data-opaline-block-id, and the editor now exposes copy/insert flows for stable heading and block links.
  • Dynamic relationship map: the map keeps file, heading, block, and concept relations separate, can focus on the active note context, and lets users inspect edge details.

Today Conversation

Today is an experimental low-friction capture surface, not a disposable chat shell. It is currently hidden in the public alpha while the focused workspace is polished. The intended model is that the user's raw text is appended to today's HTML journal first. If AI is configured, the assistant reply is appended too.

Why HTML

HTML is not the goal by itself. The goal is durable rich knowledge. HTML is attractive because it is readable, publishable, structured, AI-friendly, interaction-friendly, multilingual, and portable.

The product advantage is not merely using HTML. The advantage is maintaining clean HTML that remains useful for years.

Proposed Stack

  • Tauri 2 for the native shell
  • React for UI
  • Tiptap on ProseMirror for rich editing
  • SQLite for metadata, search indexes, links, mentions, tags, app state, and optional embeddings
  • File system storage for HTML notes and assets

Local history lives under .opaline/history/ beside other app metadata, not in notes/. Git-friendly workflows may become an advanced optional feature later, but Git is not the basic history path.

Short-Term Roadmap

  1. Polish the serious workspace so the file pane, side panels, and editor feel coherent.
  2. Add workspace migration when users change locations.
  3. Polish file context actions and add richer controls for local history, including future retention choices such as 7, 30, 90 days, forever, or size caps.
  4. Improve the relationship-map view beyond the first context and edge-detail pass: better layout, saved map presets, and clearer navigation from edges back to exact targets.
  5. Add ordinary-user creation flows for concept links and cross-note heading/block targets from the editor context menu.
  6. Improve HTML-native editing affordances so rich blocks feel like interactive UI rather than hidden markup.
  7. Continue hardening the Opaline HTML Profile with parser-based validation and tests.
  8. Deepen SQLite FTS search, metadata scanning, mentions, and broken-link repair.
  9. Add AI retrieval over local notes with visible sources before generated answers.
  10. Add explicit AI-assisted note operations: summarize, extract tags, suggest links, split notes, and create outlines.
  11. Later: static publishing and reader-facing concept search over public notes.
